================================================================================
「久未登录 / 久未访问」回归弹窗 — 可行性分析
================================================================================
（基于当前 music 小程序与 backend 代码结构，2026-05）

一、结论
--------------------------------------------------------------------------------
可以做，且与现有「每日只弹一次」模式（首页眠家横幅、mb_home_mianjia_entry_dismissed_date）
一致。需先明确「上次 xxx」指什么，再选记录方式与弹窗时机。

MVP：本地 last_visit_at + 首页 onShow + 按天去重，约半天可上线。
跨设备 / 运营统计：users 表增加 last_seen_at / last_login_at，登录或拉个人中心时更新。


二、先分清三种「上次」
--------------------------------------------------------------------------------
含义                    典型场景                              现状
--------------------------------------------------------------------------------
上次打开小程序          「你已经 7 天没来了」                  未记录；可在每次 onShow 写本地时间
上次手机号登录          「登录后去制作贺卡 / 兑积分」          仅在 mine.js 登录成功写 storage；
                                                              users 表只有 created_at，无 last_login_at
上次完成某行为          「上次制作贺卡是 3 天前，再来一张」    可用 cardData、作品列表等推断

说明：
- 微信小程序没有传统 Web 的「会话过期」；用户常未点手机号登录也能浏览。
- 文案写「距离上次登录」→ 与 mine 页授权登录对齐。
- 文案写「好久不见」→ 更适合用「上次进入小程序」。


三、推荐实现（轻量 MVP）
--------------------------------------------------------------------------------
【记录 — 本地 storage】
  mb_last_visit_at          每次 app.onShow 更新（分享贺卡冷启动跳转 gift 前先判断，避免抢焦点）
  mb_last_phone_login_at    mine.js 登录成功处写入
  mb_welcome_back_shown_date  可选：同一天只弹一次（与眠家横幅同套路）

【判断逻辑】
  gap = now - last_visit_at
  若 gap >= N 天（可配置，如 3 / 7）且今日未弹过 → 展示

【展示位置（优先级）】
  1. 首页 pages/create/create.js 的 onShow（主入口，已有横幅逻辑可并列）
  2. 或闪屏结束后 splash.js → goMain() 再弹（强运营，晚约 2 秒）
  3. 不建议：收礼页 gift、分享冷启动 routeIncomingShareGift 场景（打断收礼）

【文案示例（按业务）】
  - 久未访问：好久不见，已经 5 天没来了～ 今晚做一张助眠贺卡送给 TA？
  - 久未登录：登录后即可分享贺卡得积分，去完成今日任务 ›
  - 久未制作：距离你上次制作贺卡已 7 天，换一首曲子试试？ → 跳转 card-edit

【交互】
  - 主按钮：去制作 / 去登录 / 领积分
  - 次按钮：「今天不再提示」（写 dismiss date）
  - 体验更好时：复用 points-reward-modal 风格自定义组件，少用系统 wx.showModal


四、跨设备 / 防清缓存（可选后端）
--------------------------------------------------------------------------------
users 表增加：
  last_seen_at      任意带 openid 的请求或进首页时更新
  last_login_at     POST /api/user/login 成功时更新

接口可返回 daysSinceLastVisit，前端只负责展示。


五、注意点
--------------------------------------------------------------------------------
1. 频率：建议间隔 ≥3 天，且每日最多 1 次，避免每次打开都烦。
2. 与分享进线冲突：app.js 分享进 gift 时不要弹欢迎回归。
3. 未登录用户：用 last_visit_at 即可；勿强绑「登录」文案。
4. 合规：避免虚假倒计时、夸大积分；文案与真实任务规则一致。


六、相关代码位置（便于实现时对照）
--------------------------------------------------------------------------------
  app.js                          onLaunch / onShow；routeIncomingShareGift
  pages/splash/splash.js            闪屏、分享贺卡跳转
  pages/create/create.js          首页 onShow、眠家横幅 dismiss 逻辑
  pages/mine/mine.js              手机号登录成功
  backend/src/app.js              POST /api/user/login；users 表结构
  utils/mianjia 与 create.js      MIANJIA_HOME_BANNER_DISMISS_KEY 可参考


七、落地前需产品确认的三项
--------------------------------------------------------------------------------
1. 弹「久未打开」还是「久未手机号登录」？
2. 阈值几天（例如 3 / 7）？
3. 主按钮跳转：制作贺卡 / 积分任务 / 商城？

确认后可改：create.js + app.js（+ 可选 backend 字段）。
